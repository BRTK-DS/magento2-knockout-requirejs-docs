🚀 Wprowadzenie

Co to jest?

Magento2 to nowoczesna platforma e-commerce, która wykorzystuje zaawansowane technologie front-end do budowania interaktywnych interfejsów użytkownika. Trzy główne elementy tej dokumentacji to:

Magento2

Platform e-commerce zorientowana na architektę modułową z potężnymi możliwościami dostosowania i rozszerzenia.

KnockoutJS

Framework JavaScript do tworzenia dynamicznych interfejsów użytkownika za pomocą reactive data binding.

RequireJS

Module loader dla JavaScriptu, który pozwala organizować kod w moduły i zarządzać zależnościami.

Dlaczego razem?

Magento2 używa RequireJS do zarządzania modułami JavaScript i KnockoutJS do tworzenia reaktywnych komponentów UI. Ta kombinacja pozwala na:

  • Modularny, łatwy do utrzymania kod
  • Reaktywne wiązanie danych (data binding)
  • Efektywne zarządzanie zależnościami
  • Prosty proces rozszerzania funkcjonalności
ℹ️ Uwaga: Magento2 stopniowo przechodzi na Vue.js, ale KnockoutJS jest nadal szeroko używany w wielu instalacjach.

🏪 Magento2

Magento2 ma dobrze zdefiniowaną strukturę katalogów:

magento2-project/
├── app/
│   ├── code/              # Moduły niestandardowe
│   │   └── Vendor/Module/

│   │   └── frontend/

│   └── etc/               # Globalna konfiguracja
├── pub/

│   ├── media/             # Pliki mediów

├── var/
│   ├── cache/
│   ├── log/
│   └── generation/
└── vendor/                # Zależności Composer

Katalog View

Najważniejszy dla front-endu. Zawiera:

Katalog Opis
view/frontend/ Pliki widoczne dla klientów
view/adminhtml/ Pliki dla panelu administracyjnego
layout/ Pliki XML definiujące strukturę stron
templates/ Szablony PHTML (PHP + HTML)
web/ CSS, JavaScript, obrazy

Konfiguracja Modułu

Każdy moduł musi mieć plik konfiguracyjny etc/module.xml:

XML
<?xml version="1.0"?>
<config xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
        xsi:noNamespaceSchemaLocation="urn:magento:framework:Module/etc/module.xsd">
    <module name="Vendor_Module" setup_version="1.0.0">
        <sequence>
            <module name="Magento_Catalog"/>
        </sequence>
    </module>
</config>

Załadowanie JavaScriptu w Magento2

JavaScript ładowany jest za pośrednictwem pliku layout lub require.js:

XML (Layout File)
<?xml version="1.0"?>
<page xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance" xsi:noNamespaceSchemaLocation="...">
    <body>
        <referenceContainer name="content">
            <block class="Magento\Framework\View\Element\Template" 
                   name="my.custom.block" 
                   template="Vendor_Module::mytemplate.phtml"/>
        </referenceContainer>
    </body>
</page>
💡 Tip: Zawsze umieszczaj swoje pliki JavaScript w view/frontend/web/js/ i CSS w view/frontend/web/css/

⚡ KnockoutJS

Czym jest KnockoutJS?

KnockoutJS to biblioteka JavaScript, która implementuje wzorzec Model-View-ViewModel (MVVM). Umożliwia automatyczne synchronizowanie danych między modelem a widokiem.

Kluczowe Koncepty

1. Observable (Obserwowalne)

Observable to reaktywna zmienna, która powiadamia wszystkie zależności o zmianach:

JavaScript
define([], function() {
    'use strict';
    
    return {
        myObservable: ko.observable('Wartość początkowa'),
        myComputed: ko.computed(function() {
            return 'Obliczona: ' + this.myObservable();
        }, this)
    };
});

2. Bindingi

Bindingi łączą elementy HTML z danymi. Najpopularniejsze:

Binding Zastosowanie
data-bind="text: observable" Wyświetlanie tekstu
data-bind="value: observable" Wartość input/select
data-bind="click: funkcja" Obsługa kliknięcia
data-bind="foreach: tablica" Pętla po elementach
data-bind="visible: warunek" Warunkowa widoczność
data-bind="css: {klasa: warunek}" Warunkowe klasy CSS

3. Komponenty

Komponenty to reużywalne bloki kodu z własnym szablonern i logiką:

JavaScript - Rejestracja Komponentu
ko.components.register('my-component', {
    viewModel: {
        createViewModel: function(params) {
            return {
                message: ko.observable('Cześć!'),
                items: ko.observableArray([1, 2, 3])
            };
        }
    },
    template: `
        <div class="my-component">
            <p data-bind="text: message"></p>
            <ul data-bind="foreach: items">
                <li data-bind="text: $data"></li>
            </ul>
        </div>
    `
});

4. Computed Observables

Automatycznie przeliczane wartości zależne od innych observables:

JavaScript
var viewModel = {
    firstName: ko.observable('Jan'),
    lastName: ko.observable('Kowalski'),
    fullName: ko.computed(function() {
        return this.firstName() + ' ' + this.lastName();
    }, this)
};

console.log(viewModel.fullName()); // "Jan Kowalski"

Zaawansowane Techniki

Subscriptions (Subskrypcje)

Reaguj na zmiany w observables:

JavaScript
myObservable.subscribe(function(newValue) {
    console.log('Nowa wartość:', newValue);
});

myObservable('nowa wartość'); // Wyświetli: "Nowa wartość: nowa wartość"

Custom Bindings

Stwórz własne bindingi dla specjalistycznych wymagań:

JavaScript
ko.bindingHandlers.highlight = {
    update: function(element, valueAccessor) {
        var value = valueAccessor();
        if (value()) {
            $(element).addClass('highlighted');
        } else {
            $(element).removeClass('highlighted');
        }
    }
};

// Użycie: data-bind="highlight: isHighlighted"

📦 RequireJS

Czym jest RequireJS?

RequireJS to biblioteka JavaScript, która implementuje module pattern i zarządza zależnościami między modułami. Pozwala na ładowanie plików asynchronicznie i organizowanie kodu w logiczne moduły.

Koncepty Podstawowe

1. Definicja Modułu

Każdy plik JavaScript to potencjalnie moduł. Definiuje się go za pomocą define():

JavaScript
// Moduł bez zależności
define(function() {
    return {
        greet: function(name) {
            return 'Cześć, ' + name;
        }
    };
});

// Moduł ze zależnościami
define(['jquery', './helper'], function($, helper) {
    return {
        doSomething: function() {
            helper.doTask();
        }
    };
});

2. Załadowanie Modułu

Załaduj moduł za pomocą require():

JavaScript
require(['./mymodule'], function(mymodule) {
    console.log(mymodule.greet('Piotr')); // "Cześć, Piotr"
});

3. Konfiguracja RequireJS

W Magento2 konfiguracja RequireJS znajduje się w require.js i require-config.js:

JavaScript
var config = {
    paths: {
        'jquery': 'lib/jquery/jquery.min',
        'knockout': 'lib/knockout/knockout',
        'mymodule': 'js/mymodule'
    },
    shim: {
        'jquery': {
            exports: 'jQuery'
        }
    },
    map: {
        '*': {
            'myalias': 'js/actual-module'
        }
    }
};

require.config(config);

Ścieżki i Aliasy

Domyślne Ścieżki w Magento2

Alias Ścieżka
jquery lib/jquery/jquery
knockout lib/knockout/knockout
mage/utils/wrapper js/mage/utils/wrapper
uiComponent ui/component

Tworzymy Własny Moduł z Aliasem

XML (require-config.js)
<?xml version="1.0"?>
<config xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"

</config>

Praktyczne Przykłady

Moduł z Logiką Biznesową

JavaScript (view/frontend/web/js/mymodule.js)
define(['jquery', 'ko'], function($, ko) {
    'use strict';
    
    var MyModule = {
        isInitialized: ko.observable(false),
        
        init: function() {
            console.log('Inicjalizowanie MyModule');
            this.bindEvents();
            this.isInitialized(true);
        },
        
        bindEvents: function() {
            $('.my-button').on('click', this.handleClick.bind(this));
        },
        
        handleClick: function() {
            alert('Button został kliknięty!');
        }
    };
    
    return MyModule;
});

Załadowanie Modułu w HTML

HTML (PHTML Template)
<script>
require(['Vendor_Module/js/mymodule'], function(mymodule) {
    mymodule.init();
});
</script>

🔗 Integracja - Wszystko Razem

Jak Magento2, KnockoutJS i RequireJS Współpracują?

Trzy technologie tworzą harmonijny ekosystem:

Przepływ Pracy:
  1. Magento2 ładuje szablony PHTML
  2. Szablon zawiera JavaScript załadowany przez RequireJS
  3. JavaScript moduł używa KnockoutJS do reaktywnych widoków

Pełny Przykład Integracji

Krok 1: Tworzenie Szablonu PHTML

PHTML (view/frontend/templates/mytemplate.phtml)
<div id="my-component">
    <h2 data-bind="text: title"></h2>
    <input type="text" data-bind="value: userInput, event: {blur: saveInput}" />
    <button data-bind="click: submitForm">Wyślij</button>
    
    <ul data-bind="foreach: items">
        <li>
            <span data-bind="text: name"></span>
            <button data-bind="click: $parent.removeItem">Usuń</button>
        </li>
    </ul>
</div>

<script type="text/javascript">
require(['Vendor_Module/js/mycomponent'], function(MyComponent) {
    ko.applyBindings(MyComponent, document.getElementById('my-component'));
});
</script>

Krok 2: Tworzenie Modułu JavaScript z KnockoutJS

JavaScript (view/frontend/web/js/mycomponent.js)
define(['jquery', 'knockout'], function($, ko) {
    'use strict';
    
    return {
        title: ko.observable('Mój Komponent'),
        userInput: ko.observable(''),
        items: ko.observableArray([
            { name: ko.observable('Pozycja 1') },
            { name: ko.observable('Pozycja 2') }
        ]),
        
        saveInput: function() {
            console.log('Zapisano:', this.userInput());
        },
        
        submitForm: function() {
            $.ajax({
                url: '/api/save',
                type: 'POST',
                data: {
                    input: this.userInput()
                },
                success: function(response) {
                    console.log('Zapisano na serwerze!', response);
                }
            });
        },
        
        removeItem: function(item) {
            this.items.remove(item);
        }
    };
});

Krok 3: Konfiguracja Layoutu

XML (view/frontend/layout/default.xml)
<?xml version="1.0"?>
<page xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance" 
      xsi:noNamespaceSchemaLocation="urn:magento:framework:View/Layout/etc/page_configuration.xsd">
    <body>
        <referenceContainer name="content">
            <block class="Magento\Framework\View\Element\Template" 
                   name="mycomponent.block" 
                   template="Vendor_Module::mytemplate.phtml"/>
        </referenceContainer>
    </body>
</page>

Architektura Komponentu UI

W Magento2 komponenty UI to zaawansowana implementacja integracji:

JavaScript (view/frontend/web/js/ui/component/mycomponent.js)
define([
    'uiComponent',
    'ko',
    'jquery'
], function(Component, ko, $) {
    'use strict';
    
    return Component.extend({
        defaults: {
            template: 'Vendor_Module/mycomponent',
            items: []
        },
        
        initialize: function() {
            this._super();
            this.initItems();
        },
        
        initItems: function() {
            this.items = ko.observableArray(this.items);
        },
        
        addItem: function(item) {
            this.items.push(item);
        }
    });
});
⚠️ Ważne: Komponenty UI oferują lepszą integrację z Magento2 niż surowy KnockoutJS. Zawsze używaj uiComponent dla nowych projektów.
