🚀 Wprowadzenie

Magento 2 to bardzo rozbudowana platforma e-commerce, która łączy w sobie backend, system layoutów, renderowanie warstw front-end i architekturę modułową. W praktyce front-end Magento opiera się głównie na:

Magento 2

Framework aplikacji, system layoutów, moduły, blokowanie, template engine oraz integracja z PHP.

RequireJS

Ładuje moduły JavaScript, tworzy zależności i organizuje kod w logiczne jednostki.

KnockoutJS

Wprowadza model ViewModel, data binding i reaktywność na poziomie UI.

To połączenie sprawia, że w Magento 2 możemy pisać dynamiczne widoki, bez potrzeby odświeżania strony, z zachowaniem porządnej organizacji kodu. W praktyce RequireJS ładował moduły, a KnockoutJS obsługiwał stan UI i aktualizację widoku.

Warto wiedzieć: Magento 2 używa wielu wyróżniających się mechanizmów front-endowych, ale KnockoutJS i RequireJS są nadal fundamentem dla wielu istniejących integracji i rozwiązań custom.

🏪 Magento 2

1. Architektura modułowa

Magento 2 jest zbudowany na zasadzie modułów. Każdy rozszerzalny segment to samodzielne rozwiązanie z własnymi:

  • kontrolerami,
  • modelami danych,
  • bloku layoutu,
  • szablonami PHTML,
  • zasobami front-endowymi.
app/
├── code/
│   └── Vendor/
│       └── Module/
│           ├── Block/
│           ├── Controller/
│           ├── Model/
│           ├── view/
│           │   ├── frontend/
│           │   │   ├── layout/
│           │   │   ├── templates/
│           │   │   └── web/
│           └── etc/
├── design/
└── etc/

2. Katalog view/frontend

To główny obszar odpowiedzialny za pliki front-end. W praktyce najczęściej spotykamy tam:

Folder Rola
layout Definicje layoutów XML i instancje bloków.
templates Szablony PHTML renderowane przez PHP/HTML.
web/js Pliki JavaScript modułów.
web/css Style CSS modułu.
web/images Obrazy, ikony i zasoby graficzne.

3. Layout i blok

Magento używa pojęcia layoutu do łączenia komponentów i szablonów. Layout XML opisuje, co ma zostać wstawione na stronie i w której sekcji.

<page xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
      xsi:noNamespaceSchemaLocation="urn:magento:framework:View/Layout/etc/page_configuration.xsd">
    <body>
        <referenceContainer name="content">
            <block class="Magento\Framework\View\Element\Template"
                   name="custom_block"
                   template="Vendor_Module::example.phtml" />
        </referenceContainer>
    </body>
</page>

4. Rozszerzenie modułu

Każdy moduł w Magento ma definicję w etc/module.xml oraz wpis w rejestracji modułów:

<?xml version="1.0"?>
<config xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
        xsi:noNamespaceSchemaLocation="urn:magento:framework:Module/etc/module.xsd">
    <module name="Vendor_Module" setup_version="1.0.0">
        <sequence>
            <module name="Magento_Catalog"/>
        </sequence>
    </module>
</config>
Tip: Prawidłowa struktura katalogów i zgodność z konwencją Magento są kluczowe dla poprawnego działania front-endu.

⚡ KnockoutJS

1. Czym jest KnockoutJS?

KnockoutJS jest biblioteką JavaScript opartą na modelu MVVM. Umożliwia powiązanie danych z widokiem ViewModel i automatyczną synchronizację pomiędzy stanem danych a interfejsem użytkownika.

Najważniejsze korzyści:

  • reaktywność danych,
  • mniej ręcznego manipulowania DOM,
  • czytelny kod UI,
  • łatwiejsze utrzymywanie formularzy i list.

2. Observable

Observable to funkcja, która śledzi zmiany wartości i automatycznie odświeża wiązania w szablonie.

var vm = {
    title: ko.observable('Magento 2'),
    count: ko.observable(1)
};

vm.title('Nowy tytuł');
console.log(vm.title());

3. Computed

Computed obsługuje obliczane wartości, które zależą od innych obserwabli. Są wywoływane automatycznie po zmianie źródła.

var vm = {
    firstName: ko.observable('Jan'),
    lastName: ko.observable('Kowalski')
};

vm.fullName = ko.computed(function () {
    return vm.firstName() + ' ' + vm.lastName();
});

console.log(vm.fullName());

4. Data binding

Najważniejszy element KnockoutJS to data-bind. Pozwala łączyć model z elementami HTML.

Binding Cel
text Wyświetlanie tekstu.
value Połączenie z inputem.
click Obsługa kliknięcia.
foreach Pętla po tablicy.
visible Widoczność warunkowa.
css Dynamiczna klasa CSS. 
<div>
    <h2 data-bind="text: title"></h2>
    <input type="text" data-bind="value: searchTerm" />
    <button data-bind="click: submit">Zatwierdź</button>
    <ul data-bind="foreach: items">
        <li data-bind="text: $data"></li>
    </ul>
</div>

5. Własne bindingi

W praktyce możesz rozszerzać Knockout o własne bindingi dla konkretnego UI. Jest to bardzo wygodne w projektach Magento.

ko.bindingHandlers.highlight = {
    update: function (element, valueAccessor) {
        var enabled = valueAccessor();
        $(element).toggleClass('highlight', !!enabled());
    }
};
Uwaga: Lepsza praktyka polega na utrzymywaniu prostego ViewModelu i nie mieszaniu logiki biznesowej z warstwą prezentacji.

📦 RequireJS

1. Czym jest RequireJS?

RequireJS jest loaderem modułów JavaScript. Umożliwia organizowanie kodu w moduły, deklarowanie zależności oraz ich asynchroniczne ładowanie.

W Magento 2 jest to warstwa, która w praktyce pozwala na ładowanie plików JS bez konfliktów i z większą kontrolą nad kolejnością i zależnościami.

2. Definicja modułu

define(['jquery'], function ($) {
    'use strict';

    return {
        init: function () {
            $('#example').text('Witaj w Magento');
        }
    };
});

3. Ładowanie modułu

require(['Vendor_Module/js/example'], function (example) {
    example.init();
});

4. Konfiguracja RequireJS

W Magento 2 często konfiguruje się ścieżki, aliasy i shimy. Typowe pliki to requirejs-config.js lub konfiguracje zdefiniowane w module. Pozwala to zminimalizować ręczne importowanie JS na poziomie szablonów.

var config = {
    paths: {
        'myWidget': 'Vendor_Module/js/myWidget',
        'ko': 'Magento_Ui/js/lib/knockout/bindings/knockout'
    },
    shim: {
        'jquery': {
            exports: 'jQuery'
        }
    }
};

5. Aliasy i zależności

Aliasy pomagają w utrzymaniu czytelnego i stabilnego kodu. W Magento zamiast pisać długie ścieżki, używa się symbolicznych nazw.

Alias Opis
jquery Biblioteka jQuery.
ko KnockoutJS.
uiRegistry Rejestr komponentów UI.
Magento_Ui/js/lib/knockout/template/renderer Specjalistyczne moduły Magento UI.
Kluczowa zasada: RequireJS rozwiązuje zależności, a KnockoutJS opisuje stan UI. To dwa różne poziomy abstrakcji, które współpracują w jednej aplikacji.

🔗 Integracja Magento 2 + KnockoutJS + RequireJS

1. Jak to działa razem?

W praktyce Magento 2 ładuje szablon PHTML, który ma odwołanie do JavaScript. To odwołanie jest obsługiwane przez RequireJS. Z kolei w module JavaScript włączamy KnockoutJS, tworząc ViewModel i wiążąc dane z HTML za pośrednictwem data-bind.

<div id="my-component">
    <h2 data-bind="text: title"></h2>
    <input type="text" data-bind="value: inputValue" />
    <button data-bind="click: save">Zapisz</button>
</div>

<script type="text/javascript">
require(['Vendor_Module/js/myComponent'], function (MyComponent) {
    ko.applyBindings(new MyComponent(), document.getElementById('my-component'));
});
</script>

2. Przykładowy moduł JS

define(['ko'], function (ko) {
    'use strict';

    return function MyComponent() {
        this.title = ko.observable('Przykład Magento');
        this.inputValue = ko.observable('');

        this.save = function () {
            console.log('Wartość:', this.inputValue());
        }.bind(this);
    };
});

3. Magento UI Components

W nowoczesnym Magento 2 najczęściej wykorzystuje się komponenty UI (uiComponent) z budową przyjazną dla architektury platformy. To podejście jest bardziej zgodne z podejściem Magento niż surowy Knockout w prostych blokach.

define([
    'uiComponent',
    'ko'
], function (Component, ko) {
    'use strict';

    return Component.extend({
        defaults: {
            template: 'Vendor_Module/my-template',
            items: ko.observableArray([])
        },

        initialize: function () {
            this._super();
            this.loadItems();
        },

        loadItems: function () {
            this.items.push({ name: 'Produkt 1' });
            this.items.push({ name: 'Produkt 2' });
        }
    });
});
Dobry kierunek: Dla nowych projektów preferuj komponenty UI, a dla prostych integracji czy szybkich modyfikacji — klasyczny KnockoutJS z RequireJS.

💻 Praktyczne przykłady

Przykład 1: prosty formularz

<form data-bind="submit: submitForm">
    <label>Imię:</label>
    <input type="text" data-bind="value: firstName" />

    <label>Email:</label>
    <input type="email" data-bind="value: email" />

    <button type="submit" data-bind="enable: isValid">Wyślij</button>
</form>
define(['ko'], function (ko) {
    'use strict';

    return function FormVm() {
        this.firstName = ko.observable('');
        this.email = ko.observable('');

        this.isValid = ko.computed(function () {
            return this.firstName().length > 0 && this.email().length > 0;
        }, this);

        this.submitForm = function () {
            if (!this.isValid()) {
                return;
            }

            console.log('Formularz poprawny', {
                firstName: this.firstName(),
                email: this.email()
            });
        }.bind(this);
    };
});

Przykład 2: lista dynamiczna

<ul data-bind="foreach: items">
    <li>
        <span data-bind="text: name"></span>
        <button data-bind="click: $parent.removeItem">Usuń</button>
    </li>
</ul>
<button data-bind="click: addItem">Dodaj</button>
define(['ko'], function (ko) {
    'use strict';

    return function ListVm() {
        this.items = ko.observableArray([
            { name: 'Produkt 1' },
            { name: 'Produkt 2' }
        ]);

        this.addItem = function () {
            this.items.push({ name: 'Nowy produkt' });
        }.bind(this);

        this.removeItem = function (item) {
            this.items.remove(item);
        }.bind(this);
    };
});

Przykład 3: integracja z AJAX

define(['ko', 'jquery'], function (ko, $) {
    'use strict';

    return function AjaxVm() {
        this.result = ko.observable('');

        this.loadData = function () {
            $.ajax({
                url: '/rest/V1/example',
                type: 'GET',
                success: function (response) {
                    this.result(response.message || 'OK');
                }.bind(this),
                error: function () {
                    this.result('Błąd żądania');
                }.bind(this)
            });
        }.bind(this);
    };
});

✅ Best practices

1. Zachowaj czysty podział odpowiedzialności

Model danych, logika widoku i renderowanie to trzy odrębne warstwy. W KnockoutJS nie powinieneś mieszać logiki backendowej z widokiem. Zasadniczo ViewModel ma tylko dane i operacje potrzebne do interakcji.

2. Używaj komponentów i modułowości

Dziel kod na małe, niezależne moduły. Dzięki temu łatwiej utrzymać projekt i debugować błędy. Dobrze sprawdzają się małe pliki JS z jasno określonym zakresem.

3. Staraj się unikać bezpośredniego manipulowania DOM

KnockoutJS został zaprojektowany po to, by pracować z danymi i bindowaniem, a nie z ręcznym modyfikowaniem elementów DOM. Jeśli konieczne, używaj bindingów lub dedykowanych metod.

4. Zachowuj czytelne nazewnictwo

Nazwy funkcji, VM i bindingów powinny odzwierciedlać ich cel. Unikaj skrótów, które są zrozumiałe tylko dla pojedynczego developera.

5. Dobrze konfigurować RequireJS

Definiuj aliasy i ścieżki w jednym miejscu. To redukuje ryzyko błędów z nieznalezionymi modułami oraz ułatwia migracje podczas rozwoju systemu.

6. Pamiętaj o optymalizacji loadingu

W Magento 2 nie warto ładować każdego skryptu globalnie. Wybieraj ładowanie warunkowe i zależności zgodnie z zadaniem danego obszaru strony.

Dobry standard: prosty teoretyczny wzorzec: Magento 2 layout → PHTML → RequireJS → KnockoutJS ViewModel → UI / AJAX / backend.

🔧 Debugowanie i typowe błędy

1. Moduł nie jest znaleziony

Najczęstszy błąd w Magento 2 dotyczy błędnej ścieżki lub nieprawidłowego aliasu.

  • Sprawdź, czy plik istnieje w prawym katalogu.
  • Upewnij się, że ścieżka w RequireJS jest poprawna.
  • Sprawdź, czy moduł nie ma błędów składniowych.

2. Binding nie działa

Najczęstsza przyczyna to:

  • brak wywołania ko.applyBindings,
  • niepoprawny identyfikator elementu,
  • niewłaściwy ViewModel,
  • niezainicjalizowany obiekt ko.
require(['ko'], function (ko) {
    var vm = { title: ko.observable('Hello') };
    ko.applyBindings(vm, document.getElementById('app'));
});

3. Błąd w data-bind przy wielu elementach

Gdy używasz pętli foreach lub dynamicznie renderowanych elementów, upewnij się, że:

  • wywołujesz właściwy kontekst: $parent, $root, $data,
  • nie mieszasz obiektów z wartością prostą,
  • nie odwołujesz się do nieistniejących właściwości.

4. Problem z cache i statycznymi zasobami

W Magento 2 po zmianach front-endowych warto wyczyścić cache:

bin/magento cache:clean
bin/magento cache:flush
bin/magento setup:static-content:deploy -f

5. Narzędzia do debugowania

Najczęściej używane narzędzia to:

  • DevTools w przeglądarce,
  • konsola JavaScript,
  • logi PHP / Magento,
  • inspekcja sieci dla żądań AJAX.
Pamiętaj: przy debugowaniu front-endu w Magento sprawdzaj kolejność ładowania skryptów i poprawność definicji modułów w RequireJS.

📌 Podsumowanie

Magento 2, KnockoutJS i RequireJS tworzą skuteczny zestaw narzędzi do budowy nowoczesnych, komponentowych, reaktywnych interfejsów. W praktyce:

  • Magento 2 dostarcza architekturę, layouty i moduły.
  • RequireJS zarządza zależnościami i ładowaniem JavaScript.
  • KnockoutJS zarządza stanem UI i synchronizacją z widokiem.

Zrozumienie tej relacji jest kluczem do tworzenia wydajnych, skalowalnych i bezpiecznych integracji w Magento 2.

Najważniejsze: nie traktuj tych technologii jako niezależnych komponentów — są one częścią jednej, spójnej architektury front-endowej Magento.
